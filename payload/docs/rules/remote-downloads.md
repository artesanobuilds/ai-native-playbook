## Downloadable files in BB (all projects and providers)

- Treat the browser and execution host as different computers. A filesystem Markdown link opens BB's preview; it is not a download link. Do not label it “Download” unless clicking it actually downloads.
- Use the Files plugin's Download button for any saved workspace file. Archive links also have a Download file opener. Downloads use BB's current browser origin and its existing remote connection.
- For a deliverable link, run `bb files download-link <workspace-relative-path>` in the owning thread. It returns a percent-encoded `/api/v1/plugins/files-downloads/http/download?...` path. Prefix it with the user's verified BB browser origin, keeping its port. Never use the execution host's localhost URL for a remote browser.
- Discover the browser origin from existing BB Connect pairing or Tailscale Serve configuration/session context; do not infer it from BB_SERVER_URL, which may be the CLI's internal address. Do not include access tokens in URLs. If no remote origin is known, point the user to Files → Download rather than inventing a link.
- Preserve owning thread/environment/host selection. Never read a same-named path from the server's disk when the workspace belongs to another machine. Encode query values once; preserve spaces, Unicode, `%`, `#`, and `?`.
- Check the exact browser-facing URL: successful status, attachment disposition, expected size, and checksum for binary deliverables. A local-only check does not verify a remote link. State any unverified host/login limitation.
- Prefer BB's existing file/download routes. Do not start a per-file HTTP server or expose another port by default. If BB cannot serve an artifact, use a narrowly scoped temporary service with BB Connect, or private Tailscale Serve when already configured. Never use public Funnel or publish the filesystem. Verify the remote URL and document cleanup.
- Offer previews where supported and downloads for other types; do not imply every format has a viewer. Downloads are saved bytes, not unsaved editor drafts. BB/host transport and memory limits still apply; report failures rather than returning truncated files.
